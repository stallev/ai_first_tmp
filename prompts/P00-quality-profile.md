# P00 — Профиль качества проекта (первый шаг)

## Роль
Tech Lead: помогает пользователю выбрать уровень строгости проекта и фиксирует выбор в документе.

## Когда
**Первым** после создания репозитория из шаблона — до placeholders, visual seed и P0. Gate **G0**: без профиля P0 не начинать.

## Inputs (READ FIRST)
- [`docs/meta/project_quality_profile.template.md`](../docs/meta/project_quality_profile.template.md) — уровни, матрица D1–D10, модули, security floor (канон)
- Описание продукта от пользователя (brief, роли, сроки) — если есть

## Task

Вести диалог **вопросами с вариантами ответа** (в Cursor — вопросы в чате; в Claude Code — инструмент `AskUserQuestion`), не более 4 вопросов за раз. Не выбирать за пользователя.

1. **Контекст продукта** (один блок вопросов):
   - кто пользователи и ожидаемая нагрузка (демо / внутренние / реальные пользователи);
   - есть ли платежи или чувствительные персональные данные;
   - приоритет: скорость выхода или надёжность; размер команды.
2. **Рекомендация уровня** — по правилу из профиля §2 (платежи / чувствительные PII → не ниже `standard`; реальные пользователи → не ниже `lean`). Показать 4 уровня с одной строкой «что это даёт и чего стоит», рекомендованный — первым.
3. **Выбор уровня** пользователем.
4. **Overrides** (необязательно): предложить переопределить отдельные измерения D1–D9 (чаще всего — тесты D4 / D5 и review D6). Напомнить ограничения профиля §6: security floor и Design Lab на Lean+ не отключаются.
5. **Модули стека** (профиль §4): спросить про каждый модуль «по потребности» — нужен ли он продукту; дефолты уровня показать как предвыбор.
6. Создать `docs/meta/project_quality_profile.md` по разделу «Шаблон заполненного профиля»: YAML-блок, таблица D1–D10 **только с выбранными значениями** (колонка уровня + overrides), включённые модули, обоснование (ответы пользователя), запись в журнале с датой.
7. Вывести в чат краткое резюме: уровень, overrides, модули, что это меняет в следующих шагах (какие волны docs, какие тесты, какой review).

## Forbidden
- Выбирать уровень или модули без ответа пользователя
- Ослаблять security floor (профиль §5) или выключать Design Lab на Lean / Standard / Strict
- Копировать матрицу всех уровней в `project_quality_profile.md` (только выбранные значения + ссылка на шаблон)
- Создавать другие документы, код или правила

## Verification
- [ ] `docs/meta/project_quality_profile.md` существует; `quality_profile` — один из `prototype | lean | standard | strict`
- [ ] Для каждого override записана причина
- [ ] `modules.design_lab: true`, если уровень не `prototype`
- [ ] Обоснование и строка журнала заполнены
